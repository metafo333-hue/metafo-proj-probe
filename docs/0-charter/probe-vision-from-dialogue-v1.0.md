# 第一部分 · 缘起与愿景（为什么做 · 要成为什么）

## 一、缘起与演变史（probe 的根）

### 1.1 最早期核心公式（"高效便宜有用 / 唯实效"的雏形 · 2026-04-26）
> ❝ 这个窗口主要就是完成：**最大化成本节约 × 实际效果产生 × 大模型工作流的全自动化 = 结果**。❞（47bd93f9）

这个公式是 probe 乃至 metafoclaw "高效便宜有用" 宗旨的最初基因——**成本、实效、自动化**三者相乘求结果，至今未变。

### 1.2 link-intel 的直接萌芽（链接分析源头）
> ❝ 先有个基础视频或者**链接然后进行分析**进行符合要求的二次排版创作。❞（47bd93f9）
> ❝ 自动识别 ip 定位进行**爆款视频链接分析后进行二次创作**。❞（356b8185）

### 1.3 价值观与工作方式源头
> ❝ 将**优选质量保证和成本作为唯一依据，必须要有依据**。❞（47bd93f9）→ 后来的"不唯 star 唯实效·要数据支撑"
> ❝ **派多人去各个市场调研**。❞（47bd93f9）→ 至今仍用的多 agent 扇出工作方式

### 1.4 演变对照（一脉相承 vs 已演变/否定 · 诚实标注）

| 最早期构想（2026-04） | 现状（2026-06 probe） | 关系 |
|---------------------|---------------------|------|
| 成本节约 × 实际效果 × 全自动化 = 结果 | 高效便宜有用 · 唯实效 | ✅ 延续（宗旨源头）|
| 链接 → 分析 → 成品 | 链接情报 → 情报引擎 | ✅ 延续演进 |
| 质量+成本唯一依据·要依据 | 不唯 star 唯实效·要数据 | ✅ 延续 |
| 派多 agent 调研 | 多路扇出 | ✅ 延续 |
| 多模态素材入 | 链接/图/视频/文档/文字/名字 | ✅ 延续扩展 |
| **agent 自动登录账号搜索** | **账号 0 接管 · 不模拟登录** | ❌ 被合规红线否定 |
| **视频二次创作（换人换景）** | **视频分解分析（不是处理）· 归 MetaCut** | 🔀 归并它引擎 |
| 用户自购云服务器（2.5 折）| metafoclaw 母体托管 | 🔀 已演变 |
| 命名 元察/元实 · 元商汇 | 元探（MetaProbe）| 🔀 已改名 |

> **缘起小结**：根 = 视频爆款二创 + 链接分析 + "成本×实效×自动化"公式；经**合规收敛**（自动登录 → 不爬不绕）与**职能拆分**（二创处理 → 归 MetaCut）演变为合规情报引擎。初心一脉相承，手段大幅合规化。

## 二、愿景与使命（要成为什么）

### 2.1 一句话初心（地基·不可被实现反向覆盖）
> ❝ 把一句话需求 + 任意素材，变成「多源采集 → 专业验证 → **敢担保**的情报成品」——别人给观点，元探给带可信度标签、可回放、扛得住证伪的结论。❞（综合 f9a92133/c15f6355 原话）

### 2.2 使命
> 让任何人、任何素材，都能低门槛拿到一份「**可溯源、可证伪**」的专业情报成品。

### 2.3 三阶愿景

# 第二部分 · 定位与价值（是什么 · 凭什么）

## 三、定位

> ❝ 整体升级为**情报引擎**作用。❞（c15f6355）
> ❝ 引擎之间的关系是**独立的但是可以组合**……和其他几个引擎配合就能真正起到干事的作用。❞（c15f6355）
> ❝ probe 要镶嵌进 metafoclaw 母体，是【**第一个挂载**】……母体是铁轨、你是列车，内部零改动，只对外实现 L1 契约。❞（f9a92133）

- **是**：metafoclaw 引擎矩阵中**独立可组合的情报底座**；首个远程镶嵌样本（验证"远程项目镶嵌"铁轨）。
- **不是**：交易终端 / 投顾 / 视频剪辑工具。**职能边界**：❝视频分解分析（**不是处理**）❞——做情报分析，剪辑归 MetaCut，不串台。
- **接入纪律**：走 L1 四暗号契约对接母体，不进母体仓、不写母体文档仓。

## 四、价值主张与护城河（凭什么不被大模型碾压）

### 4.1 第一性论证（元东方原话最透彻的一段）
> ❝ **信息源是第一要素**……谁都可以进行 ai 分析，但通过**付费得到的专业数据得出的结论就是不一样了**。❞（c15f6355）
> ❝ 整合……成为无可替代、**比大公司大模型还专业**的信息收集整理归纳总结输出材料。❞（c15f6355）
> ❝ **原料进结论出**：第三方原始数据不直吐，加工成独有结论（**高于原件**）。❞（f9a92133）

护城河**不在** AI 分析（大路货），**在于**：付费专业数据 + 整合 + 验证 → 产出别人得不到的独有结论。

### 4.2 两支柱
> ❝ 这个板块有两个非常重要的事情：**第一数据源，第二进行专业的审核审查**。❞（c15f6355）

- **支柱① 数据源仓库**：17 信息域 catalog + 五类接入（L 本地库 / S 自托管 / W 官方 SDK / O 官方 API / D 数据集）+ 标准19 准入门 + 适配器热插拔。❝更多的第三方真实端口数据提供才是需要费心思的❞（c15f6355）。
- **支柱② 抗污染审核**：针对❝现在的 ai 具有被污染的情况❞（c15f6355），数据与结论**多方验证**——双审 8 闸（闸0 过程留痕 + 闸1-7 结果审核：溯源 / 多源交叉 / 抗循环 / 时效×权威加权 / 矛盾检测 / 对抗证伪 / 置信标注）。详见 [audit-system-v1](../3-build/probe-audit-system-v1.md)。

### 4.3 解耦铁律
> ❝ 任意替换 api 或者信息对流程没有影响，**只对信息源的数据产生分析结果有影响**。❞（c15f6355）

L2/L3/L4 全部源无关——换源只改数据质量，不动处理流程。这是"整合壁垒可持续扩张"的工程保证。

> 比喻：元探是一座**情报炼油厂**。原油（数据源）越纯越专业，成品越值钱；炼制流程与油田无关，油田可随时替换。

# 第三部分 · 产品与市场（做什么 · 为谁）

## 五、产品形态

> ❝ 给到的素材是：**链接、图片、视频、文档、文字、名字等都可以**，通过 **ask 的沟通了解意图后进行工作**：做调研报告、视频分解分析（不是处理）、竞调报告、网站分析等。❞（c15f6355）

```
素材输入（链接/图/视频/文档/文字/名字）
   ▼  MetaAsk 澄清意图 → 任务类型 + 输出规格 + 深度档 + 交付形态
┌──┴── 元探（MetaProbe）四层架构 ──────────────┐
│ L4 整合层  拆解→重组→归纳（七段报告/conclusion）│
│ L3 验证层  双审 8 闸抗污染 / 对抗证伪（源无关） │
│ L2 采集层  素材解析 + 数据源路由 + 多源扇出      │
│ L1 接入层  适配器（registry · 热插拔 · 标准19）  │
│ ── 数据源仓库 catalog（17 域 · 统一 schema）──  │
└──┬──────────────────────────────────────────┘
   ▼  成材（引用 + 置信度 + 证据链 + aigc_flag）
 → MetaDesign 排版 / MetaCut 视频 / MetaLearn 飞轮 / GEO 分发
```

**交付形态**（同一情报内核·多形态渲染·内核只算一次）：文字 / 信息图 / HTML 交互 / PPT / 视频。形态升级 = 多花 token，不多花数据成本。

# 第四部分 · 商业与合规（怎么变现 · 不做什么）

## 八、商业模式

> ❝ 免费(公开提取)+付费(深探)❞ · ❝公开提取走免费档、深探走 cost{premium_data}，**失败不扣**❞ · ❝公开/付费**三层深度线**（公开结论/免费预览/付费深度，**不泄露付费价值**）❞（均 f9a92133）

- **底层计费**：接母体声明式管线 `契约 → dispatch → guard → wallet.debit`，按量扣费；失败不扣。
- **三层深度线**：public（公开结论·禁显结构/竞品）→ preview（免费预览·1 条简版）→ paid（付费深度·完整七段 + 竞品横评）。**验证强度本身是付费价值。**
- **前期风险隔离**：❝前期都是第三方 api 接入最大化的进行隔离风险❞（c15f6355）。

## 九、合规底线（生死线·着墨最重）

> ❝ **不自己爬数据**。❞（元东方最终定调 · 红线最凝练原话）

> 演变说明：红线曾有"不自己爬、不自己绕"的中间版，**最终收敛为「不自己爬数据」**——"绕反爬"由第三方 API 供应商担责（❝只调用接口、不管对方是什么技术方式❞），probe 自身的红线只是**不爬数据**。

| 红线 | 元东方原话 |
|------|-----------|
| 不自己爬数据 | ❝不自建爬虫、不爬取……严禁模拟登录、抓包、逆向签名、群控❞（f9a92133）|
| 账号 0 接管 | ❝不持任何用户账号凭据❞（f9a92133）|
| 个保最小必要 | ❝仅用公开元数据、不建个人档案❞（f9a92133）|
| 限流不对抗 | ❝命中限流即停 + 通知运营，不换代理对抗❞（f9a92133）|
| 第三方担责 | ❝只调用接口，不管对方是什么技术方式❞；技术非违法直嵌、有风险走第三方 API（f9a92133）|
| 弃违法源 | 已被司法判违法者（蝉妈妈 2025 赔 490 万）一律弃用 |

**金融特有红线（本次深化）**：个人征信=持牌禁区·投资建议=持牌红线（只做信息不做建议）·行情数据再分发版权（自用可/对外需授权）。

> ⚠️ **第三方担责的边界（吸收内部证伪·诚实标注）**：probe 作为调用方，**采集层**"不管第三方用什么技术取数、由其自行担责"成立；但**三处责任仍在 probe 自身、甩不给供应商**——① 把第三方数据**二次分发/白标** ② **多源聚合再处理**成新结论 ③ 个保法下**"拼成个人背调"**。这三处 probe 必须自建合规判定层，不能用"只调用接口"挡。（依据 [feasibility-v1 §调用方责任边界](../4-research/probe-github-datasource-feasibility-v1.md) + [bizmodel-review §②](../records/probe-value-presentation-and-bizmodel-review-v1.md)）

# 第五部分 · 执行与治理（怎么走 · 怎么管）

## 十、里程碑与路线

**里程碑**：
- **M1 公开档**（零成本·约 1 周）：粘贴链接 → 评级 + 结构 + 公开结论。
- **M2 付费档**（约 2-3 周）：过 C2 质量门（完成度≥80%/准确+20pct/省力≥3×/盲评≥70%）+ 人工复核 ≥80%（**不可自过·Manus 教训**）。
- **M3 大厅上架**：待母体 HttpToolClient + identity/verify + registry 三维标签。

**落地波次**（详见 [master-solution §4](../probe-master-solution-v2.md)）：
- Wave 1-3 **全零成本**（多域 catalog + 免费源 + 自托管 + 双审 8 闸验证层 + 场景路由）——可直接开工。
- Wave 4 付费源**逐个 R1 授权**：通用 ROI 序以 master-solution §4 为准（DataForSEO→天眼查→Keepa→TinEye→Crunchbase）；金融赛道内部 ROI 例外（tushare/Polygon 打头）见 [finance-track-f](../3-build/finance-track-f-design-and-competitive-v1.0.md)。
