# probe 审核体系 v1.0 · 双审八闸 + 专业标准（支柱②）

> 日期：2026-06-06 · 来源：5 路扇出调研（过程审核/事实核查/抗污染/对抗证伪/专业方法论），全部真实 GitHub + 标准查证
> 地位：本篇是 probe 第二支柱「专业审核审查」的完整设计，**取代并升级** [design-v1](probe-intelligence-engine-design-v1.md) §3 的 7 闸草案。

---

## 〇、第一性原理（一句话）

**【是什么】** probe 审核体系 = 让情报「过程可回放、结论可证伪、每条都带专业可信度标签」的双层审查机制。
**【结论】** 不带「源可靠性 + 证据强度 + 置信度」三标签、未过对抗证伪的结论，probe 一律不输出——**这是「可溯源、可证伪」与「只会分析」的分界线**。

**为什么必须有**：AI 会编造、会被污染 → 单模型单次输出不可信 → 必须 ①过程留痕可复核 ②结果多重核查 ③对抗证伪 ④专业标准背书。审核分两面：**过程审核**（分析过程本身可信吗）+ **结果审核**（结论本身真吗）。

## 一、审核体系总览（8 闸 = 闸0 过程审核 + 闸1-7 结果审核）

```
 过程审核 ──┐
   闸0 过程留痕（NEW）  trace+溯源+快照+哈希链审计 ── 贯穿全程·其它闸的元前提
            │
 结果审核 ──┤
   闸1 溯源 + 源可靠性分级      闸2 多源交叉 + 忠实度       闸3 抗循环/抗污染/抗AIGC
   闸4 时效×权威(CRAAP)         闸5 矛盾检测(NLI)           闸6 对抗证伪(D3-Judge)
   闸7 置信标注 + 证据分级 + 四眼复核
```

| 闸 | 面 | 核心动作 | 主力工具（GitHub·全免费本地优先） | 判定 |
|----|----|---------|----------------------------------|------|
| **0 过程留痕** | 过程 | 每步 prompt/源/模型/耗时入 append-only 哈希链 + run 快照 | OpenLLMetry(Apache)+Langfuse(MIT)+MLflow+W3C PROV | trace_id 贯穿 |
| **1 溯源+源可靠性** | 结果 | 来源URL+时间戳+存档哈希+PROV三元组；**Admiralty 源可靠性 A-F** | OpenLineage + 自实现评分 | E/F 级自动降级拦截 |
| **2 多源交叉+忠实度** | 结果 | 论断原子化→多源印证；**信息可信度 1-6** | FacTool/Loki(抽取)+MiniCheck/RAGAS(忠实度) | ≥2独立源+score≥0.8采信·单源标⚠️ |
| **3 抗循环/抗污染/抗AIGC** | 结果 | 识别同源循环引用 + AI生成 + 伪权威 | SemHash(去重)+Binoculars(AI文本)+C2PA(凭证) | sim>0.92坍缩·AIGC降权 |
| **4 时效×权威** | 结果 | CRAAP 五维加权；评分函数版本固定 | 自实现 + MLflow param | 旧/低权威降权 |
| **5 矛盾检测** | 结果 | 论断对 NLI 判矛盾；冲突显式并列 | nli-deberta-v3(Apache)+AlignScore+MiniCheck | contradiction>0.8标🔴 |
| **6 对抗证伪** | 结果 | opus×3视角互异生成 + opus×2默认refuted证伪 + 裁决 | D3-Judge模式 + Prometheus-Eval + Guardrails-AI | 多数票≥3/5采信·≤1/5拒 |
| **7 置信标注+四眼** | 结果 | 三级置信 + 证据强度 + ≥2审核者留痕 | LM-Polygraph(MIT)+情报界三级 | High需≥2独立源 |

## 二、闸0 过程留痕（NEW · 过程审核的元前提）

**【一句话】** 没有过程记录，后续所有结果审核都无法溯责到具体步骤——闸0 是其它 7 闸的地基。

```
输入：job_id + 触发时间 + prompt版本哈希 + 数据源列表(URL+采集时间戳) + 模型精确版本(model_id非alias)
处理：OpenTelemetry span 记每步 → append-only 写审计存储(SQLite WAL/对象存储WORM) → 每条 SHA-256 链入前条
输出：trace_id(贯穿全流水线) + run_snapshot(参数+数据版本+prompt固定·可复现) + evidence_bundle(供闸1-7引用)
```
五原则：①完整溯源链(W3C PROV) ②不可篡改(哈希链) ③确定性可复现(温度0+版本固定+prompt哈希) ④独立可验证 ⑤过程与结论物理分离。

## 三、专业标准框架（硬标准 · 给审核立规矩）

**【一句话】** 把情报界/新闻核查/审计三行业 200 年沉淀的成熟标准，固化成 probe 每条结论的强制标签。

### 3.1 Admiralty Code 双轴（源可靠性 A-F × 信息可信度 1-6）
- **源可靠性**：A完全可靠 / B通常可靠 / C基本可靠 / D通常不可靠 / E不可靠 / F无法判断
- **信息可信度**：1经多源确认 / 2可能为真 / 3可能为真(弱) / 4存疑 / 5不可能 / 6无法判断
- **铁律**：两轴**物理隔离独立评分**（防 87% 对角线偏差陷阱）；UI 先评源、再评信息。

### 3.2 证据强度分级（情报界三级 + 来源分层）
- 置信度：High(多独立源+A/B级) / Moderate(单高质量源或多中质量源) / Low(碎片化/存疑)
- 来源分层：一手>二手>三手；单源需降级；**多源三角(≥2独立源)才升信息可信度1级**

### 3.3 四眼原则 + ACH
- **四眼**：每条发布结论 ≥2 名独立审核者签字 + append-only 留痕（提出者≠批准者）
- **ACH 竞争性假设**：≥3 个竞争解释的复杂议题触发，证伪导向（找推翻而非找支持）

### 3.4 每条结论的强制元数据标签
```json
{ "source_reliability":"B", "info_credibility":"2", "confidence_level":"Moderate",
  "source_count":3, "source_types":["primary","secondary"], "evidence_strength":"Strong",
  "verification_methods":["闸2交叉","闸6证伪","ACH"], "reviewer_count":2,
  "aigc_flag":false, "last_verified":"2026-06-06T10:00Z", "trace_id":"..." }
```

## 四、对抗证伪（闸6）落地方案（呼应 R23.1 集成模式）

**【一句话】** 不接重型开源仓库，把 D3-Judge 的「角色分离+匿名裁决+预算停」模式复刻进 probe 自有 opus 编排。

```
① 生成路 opus×3（视角必须互异·禁同prompt）
   A 证据最大化(列原始来源) · B 漏洞猎取(假设结论错·找反证) · C 误读风险(用户会怎么错用)
② 证伪路 opus×2（默认 refuted=true）
   V1 CRITIC模式(对矛盾点做工具核查) · V2 纯语言推翻(给最有力反证)
③ 裁决层  Prometheus-Eval打分 + Guardrails-AI拦无据结论 + 多数票(≥3/5采信·2/5升人工·≤1/5拒)
④ 后验核查门  裁决引用的来源必须存在于 probe 数据层（防裁判自己编源）
纪律：盲评(独立评分不看他人) + sycophancy检测(改立场须有新证据) + convergence告警(全一致反而警惕)
```

## 五、审核形态：极速版 / 深度分析版双形态 · 智能界定（2026-06-10 收敛 · 取代原「审核质量恒定·不分档」）

**probe 审核分两种产品形态，由系统智能界定每个任务走哪版（默认极速兜底 + 确定性自评 + 按需升级），每版在其定位下都是精品（见 [speed-depth-tiering-v1.0](probe-speed-depth-tiering-v1.0.md)）：**

- **⚡ 极速版**（free / preview · 快速出结论）：闸0 留痕 + 闸1 溯源 + 闸2 交叉 + 闸7 置信（preview 再加闸3 抗污染 + 闸5 矛盾）。**也是认真精品**——有留痕、溯源、基本交叉，只是不做深度抗污染/对抗证伪，且**显著标注"未全验"**。
- **🔬 深度分析版**（paid · 深度全验）：闸0-7 全开 + 四眼复核 + 对抗证伪（opus×5），完整证据链 + 置信度 + 反方观点，**可溯源可证伪**。

钱买的是**深度分析版**（8 闸全验 + 对抗证伪 + 多源专业数据），不是"极速版打折"；极速版在其定位也是认真精品（留痕+溯源+交叉，诚实标注边界）。

| 维度 | 规则 |
|------|------|
| 验证形态 | ⚡极速版（闸0/1/2/7[+3/5]·快·各自精品）/ 🔬深度分析版（闸0-7全开+四眼+对抗证伪·钱买的就是它）· 智能界定走哪版 |
| 付费差异 | 深度分析版（8闸全验+对抗证伪+多源专业数据）· 次数/配额 · 输出形态 · 便捷性(异步通知/优先队列/订阅/批量/API) · 特殊服务(人工复核背书/定制/私有源/白标/SLA) |
| 成本控制 | 验证内核缓存复用（同链接/实体不重跑 8 闸）+ 默认极速兜底 + 确定性自评按需升级（资源匹配任务需要）+ 免费次数上限（按 LTV>CAC 反推） |

> 付费场景分层详见 [bizmodel review §3](../records/probe-value-presentation-and-bizmodel-review-v1.md)。

## 七、嵌入现有流程（对齐既有契约）

- L3 验证层 = 本篇 8 闸（取代 design-v1 §3 旧 7 闸）。
- **成本计入**：闸6 对抗证伪的 opus token 必须进 `meta.models_used` + `cost.base`（对齐 alignment-prelaunch A-5，否则 MetaFlow 效益层低估 probe）。
- **七段报告**：审核体系产出的「源可靠性/证据强度/置信度」标签直接喂七段报告的「①首屏速判评级」与「②真相核查」。
- **合规**：闸3 抗AIGC 复用现有 aigc_flag guard；人物类审核守个保法（即时查不落库）。
