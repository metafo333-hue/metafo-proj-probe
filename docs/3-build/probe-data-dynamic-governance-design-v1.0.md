## 一、第一性：每次数据调取都是一个「被治理的决策点」

风险清单 48 条坑，根因是同一个：**裸调用——`fetch()` / `_chat()` 直接打出去，没人在中间管**。

> 没有缓存(C1)、没有去重(F2)、没有限额(C8)、没有限流(F3)、没有合规门(L1)、没有降级(C3)……都是因为调用方和数据源之间**是空的**。

**解法不是在 48 处各补一个 if**，而是在中间插一个**统一的数据管控器（Data Governor）**——所有数据调取**必须过它、禁绕过**。它对每一次调取**动态智能地**决策：要不要调 / 调哪个 / 调几次 / 缓不缓 / 缓多久 / 降不降级 / 拦不拦。

```
            ❌ 现在：调用方 ──直接──▶ datasource/llm （裸调用·48 坑裸露）

            ✅ 目标：调用方 ──▶ 【Data Governor 数据管控器】──▶ datasource/llm
                                  ↑ 五信号融合 · 调前/调中/调后三段闸
```

「动态智能」= 不是写死的固定规则，而是**按实时信号融合判断**——同一个源，对高价值任务放开扇出、对随手查走缓存兜底；该深的深、该省的省，资源匹配真实需要（延续 speed-depth 的「确定性自评+按需升级」，从「选哪版」下沉到「每次数据怎么调」）。

## 二、五信号融合（动态决策的输入）★ 核心

每次调取前，Governor 读五路信号，融合出本次的「调取策略」：

| 信号 | 来源 | 回答 | 影响的坑 |
|------|------|------|---------|
| **① 成本信号** | [cost-metering](probe-cost-metering-design-v1.0.md) 实时累计 | 该用户/任务/源还剩多少额度 | C1/C8/Q1 |
| **② 新鲜度信号** | 数据类型时效表 | 这类数据多久过期·缓存能不能用 | C1/K2/W1 |
| **③ 质量信号** | audit 确定性自评(源数/权威/交叉/矛盾/AIGC) | 已有证据够不够·要不要再加源 | F1/D1/D2 |
| **④ 合规信号** | registry gate19 + ledger | 该源 R1 授权否/配额状态/可否再分发 | L1/L4/L6 |
| **⑤ 配额信号** | 供应商剩余额度 + QPS | 能不能打/要不要排队/限流 | F3/C8/Q1 |

> 信号**插件化**（守 speed-depth §9.2 扩展位）：决策器只读「已注册信号集」，加新信号(如 SLA/用户历史偏好) = 注册 provider，不改决策器。

## 三、三段闸（每次调取的动作流）★ 核心

```
                  ┌─────────────── 调用前 ───────────────┐
请求 ──▶ ① 缓存查 ─命中─▶ 返回(cost=0·记 cached)         省 C1/C2/M5
          │未命中
          ▼ ② 幂等去重 ─同任务同源同参在途/已得─▶ 复用    省 F2
          │新请求
          ▼ ③ 额度门 ─超额─▶ 降级极速版/拒/引导升档        堵 C8/Q1/F1
          │额度内
          ▼ ④ 合规门 ─R1未授权/配额耗尽/禁再分发─▶ 占位/换源  堵 L1/L4/L6
          │放行
          ▼ ⑤ 限流闸 ─撞 QPS/并发─▶ 令牌桶排队             堵 F3
          │得令牌
          ▼ ─────────────── 调用中 ───────────────
            ⑥ 超时 + 重试退避(上限·守配额即停·禁换代理)     堵 C3/E4/L4
          ▼ ─────────────── 调用后 ───────────────
            ⑦ 成本埋点(cost_event)                        喂 Q3
          ▼ ⑧ 质量评估(污染/同源去重/伪权威)                堵 D1/D2/D3
          ▼ ⑨ 缓存决策 ─过质量闸才缓·按②新鲜度定 TTL+抖动─   堵 K1/K2/K3
          ▼ ⑩ 确定性自评 ─不够确定─▶ 回 ③ 加源(按需升级)     接 F1/speed-depth
          ▼ 交付
```

**每段都标了堵哪条坑**——这就是「让涉及数据的每一次调取都有动态智能管控对应」的落地形态：48 条坑被收敛到 10 个动作里，集中治理而非散落。

## 四、动态分级策略表（「智能」的具体体现）

### 4.1 数据类型 × 新鲜度 × 缓存 TTL（堵 K2/W1·信号②）
| 数据类型 | 时效 | 可缓存 | TTL | 说明 |
|---------|------|-------|-----|------|
| 行情/资金费率 | 秒-分 | ⚠️短 | 5-30s | 太久=过期情报当实时 |
| 社媒热度/互动 | 分-时 | ✅ | 5-30min | 自媒体场景主力 |
| 工商/财报/专利 | 天-季 | ✅✅ | 1-7d | 变更慢·缓存收益最大 |
| 监管处罚/披露 | 事件驱动 | ✅增量 | 增量游标 | 只拉变更(W1) |
| 深探报告(LLM) | 随素材 | ✅ | 素材不变即复用 | prompt hash key(M5) |

### 4.2 任务 blast × 扇出广度 × 模型档（堵 F1/M2·信号①③）
| 任务 blast | 扇出 | 模型 | 缓存容忍 |
|-----------|------|------|---------|
| 随手查(极速) | 单源兜底 | 单模型快出 | 高(旧也行) |
| 初筛(极速+) | 2-3 源 | 单模型 | 中 |
| 决策/尽调(深度) | 多源扇出+付费源 | opus×3+×2证伪 | 低(要新鲜) |

> 自评低 → 只对**该任务**加源升级，不一刀切全开（资源匹配需要）。

### 4.3 多租户配额智能分配（堵 Q1·信号⑤）
- per-user **令牌桶**：按档位发令牌(免费档少/付费档多)，共享供应商 key 时**公平调度**，A 用户烧不光 B 的额度。
- 突发：付费用户可借未来令牌(限额内)，免费用户硬上限。

## 五、降级阶梯（任何不确定→降级·永不拒服务·永不违规）

守 speed-depth §9.2「渐进降级兜底」+ L4「配额即停不换代理」：

```
付费专业源 ──超额/限流/失败──▶ 免费官方源 ──不可用──▶ 缓存(标"非实时") ──无缓存──▶ 合规占位(needs_authorized_api)
                                                                              ▲
                                                            ❌ 绝不：换 IP/UA/破验证硬爬(L4 红线)
                                                            ❌ 绝不：直接报错拒服务(speed-depth 兜底铁律)
```

**最坏情况 = 给一个标注清楚的兜底结果，绝不「乱扣费」或「违规爬」或「系统挂」。**

## 六、为什么这是「智能」管控（而非粗暴限流）

| 粗暴静态 | 本设计·动态智能 |
|---------|----------------|
| 全局固定 QPS/额度 | 按用户档/任务blast/源状态实时取阈值 |
| 一律缓存 N 分钟 | 按数据类型时效分级 TTL+抖动 |
| 加源加到死 | 确定性自评·够了就停 |
| 超额直接拒 | 降级阶梯·兜底不拒服务 |
| 48 处各写 if | 统一 Governor·集中决策·配置驱动 |

## 七、与现有体系映射（Governor = 运行时编排器，不重造轮子）

Governor 不自己实现质量/计费/合规，它**编排**现有组件：

| 现有组件 | Governor 调用它做 |
|---------|------------------|
| [registry.py](../../app/datasources/registry.py) gate19/ledger | ④ 合规门 + 选源 |
| audit [gates.py](../../app/audit/gates.py) 8闸 | ⑧ 质量评估 + ⑩ 自评 |
| [billing.py](../../app/core/billing.py) | 计费(对用户) |
| [metering](probe-cost-metering-design-v1.0.md)(待建) | ① 成本信号 + ⑦ 埋点 |
| [pipeline.py](../../app/services/pipeline.py) | 调用方·改为经 Governor 取数 |

> 即：Governor 是把「散落的闸」串成「每次调取必经的流水线」的那根线。

## 八、可扩展（守 speed-depth §9.5·现在简单未来能长）
1. **信号走注册表**：加新信号=注册 provider，决策器不改。
2. **动作可插拔**：三段闸每个动作是独立 step，加闸=插 step。
3. **策略走配置**：TTL 表/额度表/扇出表全配置化，禁硬编码两档分支散落。
4. **接 MetaFlow 预留**：Governor 声明 capability，未来编排层统一调度数据策略。
5. **任何不认识的新信号/源→降级兜底**，不抛错。
