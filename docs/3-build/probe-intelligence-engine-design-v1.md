## 0. 一句话定位

**谁都能用 AI 分析；但喂给 AI 的是「多方付费/专业/可验证的真实数据」+ 经过「多源交叉证伪」的结论——这是无可替代的。**

MetaProbe 的价值不在「分析」（大路货），在三件大公司通用大模型给不了的事：

1. **数据源护城河**：合法、专业、多为付费的真实数据端口（不是再多接几个爬虫）。
2. **抗污染验证**：AI 会被污染，所以每一条数据、每一个结论都多源交叉、溯源、对抗证伪。
3. **解耦铁律**：信息源/API 任意热插拔——换源只改变「数据质量」，不改变「处理流程」。

> 一句话比喻：probe 是一座**情报炼油厂**。原油（数据源）越纯越专业，成品越值钱；炼制流程（采集→验证→整合）与油田无关，油田可随时替换。

## 1. 引擎矩阵中的角色与组合（独立 · 可组合）

引擎之间**独立平级**，靠统一接入契约（L1 四端点 / API-First）组合，不互相硬绑。MetaProbe 是矩阵的**数据/情报底座**，给别的引擎喂「经过验证的真材料」。

| 组合 | 协同方式 | 产出升级 |
|------|---------|---------|
| **MetaAsk → MetaProbe** | Ask 澄清意图（命根子在理解端）→ Probe 据意图选源、采集 | 不是「搜一堆」，是「按真实需求精准取证」 |
| **MetaProbe → MetaDesign** | Probe 出情报成材 → Design 排版成专业交付物 | 结论 + 审美，专业级报告 |
| **MetaProbe → MetaCut** | Probe 出视频拆解结论（脚本/钩子/选题）→ Cut 真正剪辑处理 | 「先看懂再动手」，分析与处理分离 |
| **MetaProbe → MetaLearn** | 每次作业的「源命中率/验证结果」回流飞轮 | 越用越懂「哪些源对哪类问题最准」 |
| **MetaProbe × MetaOps** | 持续监测类（舆情/竞品/价格）挂 Ops 定时巡检 | 一次性情报 → 持续情报雷达 |

**铁律**：引擎间只走 L1 契约通信，禁直连内部实现（对应 R22 五环跨环禁直连精神）。

## 2. 数据源仓库（核心 · 你问的「分类应该有哪些」）

### 2.1 仓库 = 三件东西

1. **目录/台账（catalog）**：`ledger.yaml` 升级为多域目录，每个源带统一元数据。
2. **准入门（gate）**：标准19 核验 + R1 付费授权 + 合规判定，`status=active` 才放行。
3. **适配器（adapter）**：每个源实现 `DataSourceAdapter` 统一契约 → 热插拔。

### 2.4 每个源的元数据 schema（仓库的「身份证」）

```yaml
sources:
  <source_id>:
    domain: D3                 # 信息域代号
    vendor: "..."              # 供应商
    access_type: official_api  # official_api|licensed_saas|public_authority|oss_lib|browser_fallback
    supported_kinds: [...]     # article/doc/video/social/entity/image
    authority_score: 0.0-1.0   # 权威度（喂验证层加权）
    freshness: realtime|daily|snapshot
    region: [CN, US, global]
    cost: {model: per_req, premium_data: 0.00}   # 喂 billing 三层深度线
    rate_limit: "..."
    license: MIT|Apache|commercial|...
    gate19: {...}              # 标准19 逐项，全 true 才 active
    status: pending|active|rejected
```

> 这就回答了「怎么构建仓库」：**多域目录 + 统一元数据 schema + 标准19 准入门 + 适配器热插拔**。现有 `ledger.yaml` 已是雏形，按上表 schema 扩展即可。

### 2.5 数据源策略（2026-06-06 校准 · 第三方 API 最大化隔离风险）

**前期铁律（元东方裁定）**：不自建爬取；**最大化接入成熟第三方 API**，让供应商背技术/合规责任，probe **只调接口、不背供应商责任**（延续现有 ledger 边界）。接入优先级：

1. **GitHub 开源项目提供的 API/SDK**（活跃维护、许可证清晰、可自托管或直连）——风险最低、可控性最高。
2. **运行良好网站的付费 API 服务**（成熟商用、有公司主体、有 SLA）——花钱买「现成 + 担责」，省自建省合规。
3. **官方开放 API + 公开权威库**（免费但权威，D1/D2/D5/D6/D10 大量）——零成本拉开身位。
4. **开源专业库本地化**（解析/转写/版面，已选型）——无网络无成本无风险。

**为什么是护城河**（≠ 更多爬虫，那是法律雷区）：
- **隔离风险**：第三方持牌 + 担责 → probe 不踩反爬铁律、不背技术责任。
- **整合壁垒**：把 17 信息域(D1-D17)、几十个第三方 API 统一适配 + 交叉验证，是别人懒得做的脏活。
- **不可替代**：大公司通用模型不会为你专门整合多域专业付费源 + 做抗污染验证——**整合 + 验证 = 护城河**。

**红线（最终版 · 单条）**：「不自己爬」= probe 自身不实施任何爬取（自写爬虫/抓取平台数据/模拟登录/抓包/逆向签名）。**可用**任何第三方付费/免费 API 或全自动化数据提供方（第三方如何取数由其自行担责，probe 只作调用方）；弃已被司法判违法供应商（蝉妈妈）。**独立保留**（不被此条吃掉）：个保法最小必要 / aigc_flag / 原料进结论出。

## 3. 多源验证与抗污染（信任护城河 · 你说的「识别真假」）

> 本节旧 7 闸草案已作废，完整验证层设计迁移至 [probe-audit-system-v1.md](probe-audit-system-v1.md)（支柱②真源）。

验证层是一条独立信息流处理链，**与数据源无关**（换源不影响这条链）。完整设计见 audit-system-v1 的**双审 8 闸**：

- **闸0（过程留痕）**：trace+溯源+快照+哈希链审计，贯穿全程，是其它闸的元前提
- **闸1-7（结果审核）**：溯源+源可靠性 / 多源交叉+忠实度 / 抗循环+抗污染+抗AIGC / 时效×权威 / 矛盾检测 / 对抗证伪 / 置信标注+四眼复核

**极速版 / 深度分析版双形态 · 智能界定（2026-06-10 收敛 · 见 [speed-depth-tiering-v1.0](probe-speed-depth-tiering-v1.0.md)）**：系统智能界定每个任务走哪版（默认极速兜底 + 确定性自评 + 按需升级），每版各自精品——⚡极速版（闸0/1/2/7[+3/5]·快·留痕+溯源+交叉·标注未全验）/ 🔬深度分析版（闸0-7全开+对抗证伪·可溯源可证伪）。钱买的是深度分析版（8闸全验+对抗证伪+多源专业数据），不是极速版打折；付费差异另在次数/形态/便捷/特殊服务（见 [audit-system §五](probe-audit-system-v1.md) + [bizmodel review §3](../records/probe-value-presentation-and-bizmodel-review-v1.md)），成本由缓存复用 + 确定性自评按需升级 + 免费次数上限控制。

## 4. 四层引擎架构（解耦 · 任意替换不影响流程）

```
素材输入：链接 / 图片 / 视频 / 文档 / 文字 / 名字(实体)
   │
   ▼  [MetaAsk] 意图澄清 → 任务类型 + 输出规格 + 深度档
   │
┌──┴──────────────── MetaProbe ────────────────────┐
│ L4 整合层  拆解 → 重组 → 归纳（LLM 把碎片炼成成材）  │
│ L3 验证层  双审8闸 抗污染 / 对抗证伪（源无关·见audit-system-v1）│
│ L2 采集层  素材解析 + 数据源路由 + 多源并发扇出       │
│ L1 接入层  适配器（registry 驱动 · 热插拔）           │
│ ─ 横切 ─ 数据源仓库(catalog) · 三层深度线 · 异步长任务 │
└──┬───────────────────────────────────────────────┘
   ▼  成材（带引用 + 置信度 + 证据链）
 → [MetaDesign] 排版 / [MetaCut] 视频处理 / [MetaLearn] 飞轮回流
```

**解耦铁律（你的核心要求）**：L2/L3/L4 全部**源无关**。换掉一个 L1 适配器，只改变「数据质量 → 分析结果」，**对处理流程零影响**。这正是现有 `DataSourceAdapter` + `registry` 模式提供的能力——本设计把它确立为引擎第一性原理。

### 5.4 交叉轴三：按商业档位（接三层深度线）

**访问档（极速版 / 深度分析版双形态 · 智能界定 · 见 [speed-depth-tiering-v1.0](probe-speed-depth-tiering-v1.0.md)）**：免费（公开·拉新·⚡极速版精品但限次 + 默认 L0 速判呈现 + 深度版 preview 钩子）→ 注册预览（留存·更多次数 + L1 依据层）→ 付费按次（🔬深度分析版·完整 L2 明细 + 8闸全验+对抗证伪 + 高级形态 HTML/PPT/视频）→ 订阅监测（B6/C4 持续雷达）→ 企业定制（中大 B 高客单 + 特殊服务）。钱买的是深度分析版，极速版在其定位也是认真精品。

> 引擎基座强大 = L1-L4 + 17 域(D1-D17·真源 ledger.yaml v5) + 5 业务域/27 场景模板可任意拼装；和别的引擎组合后才「真能干事」。新增一个场景 = 加一个模板（选哪几个信息域 + 哪种呈现深度 + 哪种交付形态），**不动引擎内核**。

### 5.5 交付形态矩阵（同一份情报 · 多种成品 · 用户挑）

同一份验证后的情报内核（L4 产物），可渲染成不同交付形态——**形态由 MetaAsk 按用户喜好 + token 预算选**，内核不变，只是「最后一公里」不同。这正是「所问即所得」：要什么样的成品给什么样的。

| 交付形态 | Token 成本 | 产出引擎 | 适用 |
|---------|-----------|---------|------|
| 文字 / Markdown | 最低 | Probe 自产 | 默认基础形态、快速结论 |
| 信息图 / 图表（image） | 中 | Probe 出数据 → 渲染 | 数据可视化、一图看懂 |
| HTML 交互报告 | 中高 | Probe → **MetaDesign** 排版 | 专业交付、可点击钻取（发 hub） |
| PPT / 演示稿 | 中高 | Probe → **MetaDesign** | 汇报、路演 |
| 视频 / 口播讲解 | 最高 | Probe → **MetaCut** | 高传播、自媒体分发 |

**铁律**：情报内核（采集+验证+整合）只算一次；形态是可叠加的渲染层，换形态不重做情报。**形态升级 = 多花 token，不多花数据成本。** MetaAsk 在意图澄清时就确定形态与深度档，避免「先出文字又返工做视频」。
