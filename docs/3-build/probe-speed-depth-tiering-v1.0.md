# probe · 极速版 / 深度分析版 · 智能界定方案 v1.0

> 日期：2026-06-10 · 性质：probe 两形态（极速版 / 深度分析版）的智能界定机制设计
> 背景：分档的初衷 = probe 提供「极速版（快速出结果）+ 深度分析版（深度全验）」两种产品形态，不是质量打折。本方案定**怎么智能界定每个任务走哪版**。
> 收敛：本方案统一此前"质量恒定·不分档"（2026-06-08）与"强度分档"（代码 gates.py）的口径分歧——见 §七。
> 真源：本文 = 双形态界定真源；闸定义引 [audit-system-v1](probe-audit-system-v1.md)；代码 [app/audit/gates.py](../../app/audit/gates.py)。

## 一、初衷与第一性

> probe 同一个情报内核，对外是**两种产品形态**：
> - **极速版** = 要的是「**快**」——秒级到分钟级给可用结论，用于速览/初筛/拉新。
> - **深度分析版** = 要的是「**准 + 全**」——完整证据链 + 对抗证伪，用于决策/尽调/对外发布。

**不是质量打折，是两种需求**：有人只想"10 秒知道这条链接值不值得做"，有人要"一份敢拿去做投资决策的尽调"。用一个档强行覆盖两者，要么慢得拉不到新、要么轻得不敢担保。

**智能界定 = 系统智能决定每个任务走哪版，而非让用户预先纠结选档。**

---

## 二、两形态定义（各自的"精品标准"）

| 维度 | ⚡ 极速版 | 🔬 深度分析版 |
|------|---------|-------------|
| **定位** | 快速出结论·速览/初筛/拉新 | 深度全验·决策/尽调/对外 |
| **闸位**（对齐 gates.py）| free：闸0 留痕+闸1 溯源+闸2 交叉+闸7 置信<br>preview：再加闸3 抗污染+闸5 矛盾 | paid：闸0-7 全开 + 四眼复核 + 对抗证伪（opus×5）|
| **数据源** | 默认底座 + 少量免费源·单轮 | 多源扇出 + 付费专业源·交叉 |
| **模型** | 单模型快出 | opus×3 生成 + ×2 证伪 |
| **时延 / 成本** | 秒级-分钟·低 | 分钟级+·高 |
| **精品标准** | 在"快"的定位下**可信**：有留痕、有溯源、基本交叉，**显著标注"未全验"** | **可溯源可证伪**：完整证据链 + 置信度 + 反方观点 + 对抗证伪存活 |
| **交付** | 评级 + 结构 + 公开结论（速览卡）| 七段报告 + 竞品横评 + conclusion_block |

**关键**：极速版不是"次品"，是"快品"——它在自己的定位里也是认真做的（留痕+溯源+交叉，不是瞎猜），只是不做深度抗污染/对抗证伪，且**诚实标注边界**。

## 三、智能界定机制（四信号渐进融合）★ 核心

**设计原则：默认极速兜底 → 确定性自评 → 按需智能升级。** 用户不用预选档位，系统智能路由。

### 信号 A · 意图（MetaAsk 前置分流）
MetaAsk 澄清意图时，识别两个维度：
- **速度 vs 完整**：用户话里"快速看下""值不值得"→ 速度优先；"完整报告""帮我尽调"→ 完整优先。
- **用途 blast**：随手看 / 初筛 → 低；据此做决策 / 对外发布 / 投资 → 高。

→ 用途高 blast（决策/尽调/对外/投资）**直推深度版**；速度优先 + 低 blast → 极速版。

### 信号 B · 任务类型（场景模板默认档）
27 场景模板每个挂**默认形态标签**：
- **极速默认**：链接评级、真假速判、结构速览、选题初筛…
- **深度默认**：企业背调、竞品全景、投资尽调、人物核查、危机舆情…
- **中间（看信号 A）**：网站分析、发布者画像…

### 信号 C · 确定性自评（极速版跑完的智能升级触发）★ 最关键的智能点
极速版跑完，验证层算一个 **确定性分数** = f(源数量 · 源权威度 · 交叉印证程度 · 有无矛盾 · AIGC 污染嫌疑 · 话题敏感度)：

```
极速版出结果 → 确定性自评
  ├─ 高确定（多源一致 / 高权威 / 无矛盾）→ 直接交付（标"⚡极速版·已轻验"）
  └─ 低确定（单源未证实 / 源冲突 / 高敏感话题 / AIGC 嫌疑）
        → 系统提示："此结论涉及 [X] 不确定，建议深度分析版（全验+对抗证伪）"
        → 免费用户：给 preview 钩子 + 引导付费深度版
        → 付费用户：一键 / 自动升级深度版
```

**这是智能界定的精髓**：不是一刀切，而是**极速兜底 + 不确定才升级**——该快的快、该深的深，资源投入匹配任务真实需要。

### 信号 D · 商业档位（约束 + 钩子）
- **免费用户**：极速版（free）为主 + 深度版 preview 钩子（露一角付费价值，不泄露完整）。
- **付费用户**：深度版（paid）可选 / 默认。
- 计费走母体 `契约→dispatch→guard→wallet.debit`，**失败不扣**。

### 决策流（一张图）
```
任务（素材 + 一句话）
   ▼ MetaAsk 意图澄清（信号 A）
[高 blast 决策/尽调/对外？] ──是──▶ 🔬 深度分析版（8闸全开+对抗证伪）
   │否
   ▼ 场景模板默认档（信号 B）+ 商业档位（信号 D）
⚡ 极速版（闸0/1/2/7[+3/5]）
   ▼ 确定性自评（信号 C）★
[够确定？] ──是──▶ 交付（标"⚡极速版·已轻验·重大决策建议深度版"）
   │否
   ▼ 提示升级 → 一键/自动 → 🔬 深度分析版
```

## 四、透明铁律（防误用·硬约束）

1. **极速版结果必须显著水印**："⚡ 极速版 · 轻验 · 重大决策请用深度分析版"——禁止极速版伪装成深度精品（否则用户拿轻验结果当尽调用，是信任硬伤）。
2. **深度版带"已全验·可溯源可证伪"标识** + 完整证据链 + 置信度 + 反方观点。
3. **确定性自评的"不确定"必须显式告知**，不静默降级糊弄。
4. **三层深度线切割**（public/preview/paid）叠加在形态上：public 禁显结构/竞品；preview 仅 1 条简版；paid 才给完整。

## 五、与现有体系的映射

| 本方案 | gates.py 档 | 三层深度线 | 8 闸 |
|--------|------------|-----------|------|
| ⚡ 极速版 | free / preview | public / preview | 闸0/1/2/7[+3/5]|
| 🔬 深度分析版 | paid | paid | 闸0-7 全开 + 四眼 + 对抗证伪 |

> 注：**两条轴别混**——「public/preview/paid」是**三层深度线**（对外可见性切割），「free/preview/paid」是 **gates.py 审核档名**；首层名不同（public ≠ free）是两个并存维度，非笔误。

**代码 gates.py 的分档（free/preview/paid）= 对的**，它就是双形态的技术实现，无需改。

## 六、为什么这是"智能"界定（而非粗暴分档）

| 粗暴分档 | 本方案的智能界定 |
|---------|----------------|
| 用户预先选"我要免费/付费档" | MetaAsk 意图 + 场景默认 + 自评，系统智能路由 |
| 免费一律轻、付费一律重 | **默认极速兜底，不确定才升级**——按任务真实需要投资源 |
| 轻验结果可能被当精品 | 确定性自评 + 显式水印，诚实标注边界 |
| 质量随档打折 | 每版在其定位下都是精品（极速精在快、深度精在全）|

## 七、收敛 2026-06-08"质量恒定"裁定（口径统一）

**分歧**：2026-06-08 多份文档裁定"质量恒定·不分档·所有人 8 闸全开"；但代码 gates.py 是分档；元东方初衷是"极速版/深度分析版双形态"。

**调和**：把"质量恒定"裁定的**合理内核保留**、**不可持续部分修正**——

- ✅ **保留**：「每一版在其定位下都是**精品**，不糊弄」——极速版也认真留痕+溯源+交叉，不是垃圾速成。这是"质量恒定"的真精神。
- 🔧 **修正**：「所有人都拿 8 闸全开深度版」不可持续（成本：8 闸全开 + opus×5 + 付费源，每份成本高，免费拉新烧不起）。改为**双形态智能界定**——确定性自评让"该深的深、该快的快"。

**一句话**：**质量恒定 ≠ 资源恒定**。质量恒定 = 每版都是其定位的精品（守住）；资源恒定（人人 8 闸全开）= 不可持续（放弃）。智能界定让资源投入智能匹配任务需要，既控成本又保质量底线。

> 据此，所有文档的"质量恒定·不分档·取代强度分档"表述，统一收敛为"**极速版 / 深度分析版双形态 · 智能界定（默认极速兜底 + 确定性自评 + 按需升级）· 每版各自精品**"。bizmodel-review 的"所有人精品"论证调整为"两形态各自精品 · 按形态智能界定"。

## 九、升级演进与兼容适配（面向未来·不推翻重来）

> 核心原则：**现在是极速/深度两档，但机制按"N 形态可扩展框架"设计**——以后加形态、加信号、加闸、接 MetaFlow 编排，全走扩展位，不破现有契约。

### 9.1 四个可扩展点（预留扩展位·禁硬编码两档）

| 扩展点 | 现在 | 未来怎么加（不改核心） | 设计手法 |
|--------|------|---------------------|---------|
| **① 形态可扩展** | 极速 / 深度 | 加"标准版/实时监控版/批量版"= 加一条**配置**，不改代码 | 形态注册表（tier registry · 每形态声明：闸集/源策略/模型/SLA/成本/精品标准）·延续 gates.py 的 `TIER_GATES` dict |
| **② 信号可扩展** | 意图/任务/自评/档位 4 信号 | 加"预算约束/SLA 时延/合规等级/用户历史偏好"= 注册新 **signal provider**，融合器自动纳入 | 信号插件化（每信号是独立 provider · 决策器只读"已注册信号集"，不写死 4 个）|
| **③ 闸可扩展** | 8 闸 | audit 加闸9/闸10（新验证维度）→ 形态配置**可选**是否纳入 | 形态与闸**解耦**（形态只声明"用哪些闸"·闸在 audit-system 独立演进·闸 schema 版本化）|
| **④ 自评可替换** | 规则版 f(源/权威/交叉/矛盾/AIGC/敏感度) | 换 ML 版 / LLM 版自评 | 确定性自评 = **稳定接口**（入：极速结果+证据·出：确定性分+不确定维度）·实现可替换 |

### 9.2 向后兼容的四道保险

1. **契约版本化**：manifest/invoke 的形态字段（tier/depth）版本化——新形态用**新 enum 值**，旧调用方不传则默认极速；API `/api/v1`→`/v2` 平滑过渡、兼容期并存（守 nginx 路由四禁）。
2. **渐进降级兜底**（最关键）：**任何"不认识的新信号/新形态/界定失败"→ 一律降级极速版**。极速版便宜+快+有留痕，是安全兜底——**绝不因界定逻辑本身出错而拒绝服务**。旧客户端不传新字段 → 用默认值，不报错。
3. **数据迁移规范**：形态/tier 记录在任务表用**加枚举值 + ALTER ADD COLUMN IF NOT EXISTS**（守 R27 gate_router DO 块同步铁律），不改表结构核心；存量任务默认极速。
4. **默认安全**：界定的"默认值"永远指向**最便宜+最快+有留痕**的极速版——升级新逻辑时，最坏情况是"该深的没自动升级"（用户可手动升级），而非"系统挂了/乱扣费"。

### 9.3 跨引擎复用与 MetaFlow 协同（架构上沉路径）

- **抽象为矩阵通用能力**：极速/深度界定不是 probe 专属——MetaDesign（快速草稿 vs 精修）、MetaCut（速剪 vs 精剪）同样需要"快/全"两形态。把界定框架抽到**共用 lib**或上沉 **MetaFlow 编排层**，各引擎复用。
- **MetaFlow 统一调度预留**：probe 接入 MetaFlow 后，形态界定可由编排层统一做——probe 只需声明 **形态 capability**（"我支持 fast/deep 两形态、各自的 SLA/成本"），编排层按全局策略路由。**现在就在 manifest 预留 capability 声明位**，未来零改造接入。

### 9.4 演进路线（每步都不破上一步）

```
v1（现在）  极速/深度两形态 + 四信号 + 规则版自评 + gates.py 分档
   │  ← 走扩展位，不破 v1
v1.x        加信号(预算/SLA) · 自评 ML 化 · 加"标准版"形态 · 闸9 接入
   │  ← 契约升 v2，v1 兼容期并存
v2          接 MetaFlow 统一编排 · 跨引擎复用界定框架 · 形态流水线(极速初筛→自动深度复核)
```

### 9.5 写系统时的兼容铁律（给 S1 开发·硬约束）

1. **形态 / 信号 / 闸都走注册表 + 配置**，禁硬编码 `if tier=="free"` 式两档分支散落各处——集中到一个决策器读配置。
2. **契约字段版本化 + 默认值兜底**：新增字段必给默认值，旧调用零改造可跑。
3. **新增走扩展位**：加形态/信号/闸 = 加配置/注册 provider，**不改核心决策器**。
4. **任何不确定 → 降级极速兜底**，不抛错、不拒服务、不乱扣费。
5. **manifest 预留 capability 声明**：形态/SLA/成本声明位现在就留，为 MetaFlow 编排零改造接入。

> **一句话**：现在简单（两档够用），但每个"档/信号/闸/自评"都是**可插拔的扩展位**而非写死的分支——让 probe 现在能跑、未来能长，升级永远是"加配置"不是"改架构"。
