## 0. 结论先行（GO / NO-GO）

**有条件 GO — 先做 Pilot 冒烟测试，暂不作为生产关键单点依赖。**

- ✅ **技术面通过**：平台覆盖、接口类别、SDK/文档、定价模型 4 项均有强证据支撑，覆盖 link-intel/probe 所需的全部目标平台（TikTok/抖音/小红书/Instagram/YouTube）。
- ⚠️ **证据面有硬伤**：本轮 23 条确认结论中 **~95% 来自 TikHub 第一方**（官网/文档/自家 SDK + OpenAPI spec）。第一方对"有没有、多少钱"是权威，但对"数据质量、时效、可靠性、合规"**不构成独立验证**。
- 🛑 **决定性维度全部空白**：合规/封禁风险、数据字段完整度、更新时效、可靠性/SLA、竞品横向对比——这 5 项**本轮零验证结论**，恰恰是"能否长期生产依赖"的核心。

**一句话**：可以接，但必须按"可替换的外部供应商"来接，不能按"稳定基础设施"来接。先用免费额度做一次真实接口冒烟，拿到字段/时效/成功率的实测数据再定生产化。

## 1. API 能力与覆盖面 ✅（高置信）

### 1.1 平台覆盖
- **16+ 平台，单一 API Key 贯通**。`api.tikhub.io` 实时 Swagger 标题逐字枚举：Douyin / TikTok / Xiaohongshu / Lemon8 / Bilibili / Sora2 / Kuaishou / Pipixia / Weibo / WeChat / Instagram / YouTube / Twitter / Threads / Reddit / Zhihu。
- link-intel/probe 所需平台 **全部命中**：TikTok、抖音、小红书(RED/XHS)、Instagram、YouTube。
- "16" 这个标题数字混入了工具类服务（验证码识别、临时邮箱），文档实际枚举 30+ 条，但每个**点名的核心平台都能独立核实**。
- 出处：tikhub.io · docs.tikhub.io · api.tikhub.io · GitHub SDK · PyPI（六面交叉）

### 1.2 接口规模
- **1010 个端点 / 52 个资源组**（每个 OpenAPI tag 一个资源）。
- 深度分布：**抖音 400+ 端点最深**，TikTok 200+，小红书/Instagram 80+，YouTube 50+，Bilibili 40+，Twitter/X 13+。
- SDK 自称 **1010/1010 = 100% 覆盖**（对 OpenAPI spec V5.3.2 机械生成）。
- 🔴 **关键警告**：这个"100% 覆盖/已验证"是供应商用内部脚本 `scripts/verify_coverage.py` 自证，只确认 **SDK 包了 spec 里的每个端点（代码完整度）**，**不代表端点能用、返回数据完整准确、或底层抓取稳定**。把 1010/1010 当作"代码完整度"，不是"数据质量/可用性"保证。

### 1.3 接口类别（覆盖 link-intel/probe 全部所需）
用户主页/分析 · 视频/帖子详情与统计 · 评论/回复（含**情感分析**功能）· 搜索 · 趋势/榜单 · 直播间数据(WebSocket) · 电商(TikTok Shop)。

专门分析接口（GitHub SDK 代码模块名实证，非营销话术）：
`douyin_search` · `douyin_billboard`(抖音榜单) · `douyin_xingtu`(星图) · `douyin_creator` · `tiktok_analytics`(MCN) · `tiktok_creator`(电商) · `tiktok_shop_web` · `tiktok_ads`。
单 TikTok 就有 6 个独立 API 组（Web / App V3 / Creator / Analytics / Shop Web / Ads）。

### 1.4 SDK / 文档质量 ✅
- 官方 **Python SDK**（PyPI `tikhub` v2.1.1，活跃版本，对 spec V5.3.2 机械生成+版本追踪）+ Java SDK。
- Swagger UI / ReDoc 在线（api.tikhub.io/docs）。
- 含 Sora2/Lemon8 → 说明 spec 截至 2026-06 仍在更新。
- **接入方式**：单 Key + 维护中的 SDK，无需逐平台分别申请凭据。

## 2. 定价与商业条款 ✅（高置信）

### 2.1 计费模式
- **纯按量付费（pay-as-you-go），无订阅、无月最低消费、无承诺**。
- 单端点基价 **$0.001–$0.01/请求**（不同端点不同基价，$0.001 是地板价）。
- **仅 HTTP 200 成功请求计费**，非 200 不扣费。
- ⚠️ 常见误读：以为全平台统一 $0.001。实际按端点基价浮动，成本测算**必须按具体端点组合**算。

### 2.2 阶梯折扣（按"日"请求量自动应用，边际计算）
| 日请求量 | 折扣 |
|---|---|
| 0–999 | 0% |
| 1,000–4,999 | 10% |
| 5,000–9,999 | 20% |
| 10,000–19,999 | 30% |
| 20,000–29,999 | 40% |
| **30,000+** | **50%**（$0.001 地板降到 $0.0005）|

公式：`总成本 = Σ(各档请求数 × 基价 × (1−折扣))`。官方实测样例：12,000 请求/日 @ $0.001 基价 = $10/日。

### 2.3 免费额度与入门
- 注册送 **~50 免费请求**（无需信用卡，仅邮箱验证），可访问全部 16 平台。
- **每日签到**领免费试用额度（免费额度**不过期**）。
- 推荐返 **~$2 付费余额（约 1000 请求）**。
- 默认 **10 RPS** 限流（付费套餐可提升）。
- 🔸 部分端点**只收付费余额、不收免费额度**（API 报错串实证：`Insufficient balance, this endpoint requires payment and accepts free credits`）。
- 支付：支付宝 / PayPal / Crypto。

### 2.4 企业级（中置信）
- Enterprise：**$3,000 一次性 或 $4,500 累计消费** 起，永久减免/更高承诺。
- 不取代默认按量模式。⚠️ tikhub.io/enterprise 抓取时 404，SLA/支持/专属容量等权益**未直接核实**，只确认了门槛金额。

## 3. 成本测算（link-intel / probe 场景）

> 假设最便宜端点（$0.001 地板）+ 阶梯折扣边际计算。实际端点若均价 $0.005，下表 ×5；均价 $0.01，×10。

| 日调用量 | 日成本($0.001档) | 月成本(×30) | 备注 |
|---|---|---|---|
| 1,000/日（轻量监测）| ~$1.0 | **~$30/月** | 入门级 |
| 10,000/日（中等抓取）| ~$8.6 | **~$258/月** | 主力场景 |
| 30,000/日（高频）| ~$21.6 | **~$648/月** | 触发 50% 折扣地板 |

**关键**：准确测算依赖端点单价表。需先确定 probe 的端点调用画像（每端点单价 × 日量），再用 2.2 公式算，**不能用 $0.001 地板粗估**——视频详情/搜索这类重端点很可能落在 $0.005–$0.01 区间。

## 4. 竞品对比与选型 🔍（本轮**未独立验证**，以下为背景分析，需核实）

> ⚠️ 真实性声明：研究问题要求对比 Apify/RapidAPI/官方开放平台，但本轮 23 条确认结论**全部聚焦 TikHub 自身**，未产出竞品价格/覆盖/可靠性的验证对照。下表为通用背景判断，**接入前需独立核实**。

| 方案 | 模式 | 覆盖 | 合规性 | 适配度 |
|---|---|---|---|---|
| **TikHub** | 按量 $0.001–0.01/req · 单 Key | 16+ 平台最广（抖音/XHS 深）| 抓取型，灰色 | 单 Key 多平台，集成成本最低 |
| **Apify**（clockworks 等 actor）| 按 compute/结果计费 · 逐 actor | 主流平台，actor 生态大 | 抓取型，灰色 | 逐 actor 接，多平台要拼 |
| **RapidAPI 第三方 TikTok API** | 订阅档 $0–500/月 · 各家不一 | 单平台为主，质量参差 | 抓取型，灰色 | 可靠性/维护性赌运气 |
| **官方开放平台** | 见下 | 受限 | ✅ 合规 | 多数场景不可用 |

**官方 API 现实（合规但多数不可用）**：
- **YouTube Data API** ✅ 官方、免费配额 10k units/日、合规 → **YouTube 数据强烈建议直接用官方**，不走第三方。
- **Instagram Graph API** — 仅商业/创作者账号、需 App 审核。
- **TikTok Research API** — 仅美/欧学术、申请制；Display API 能力很窄。
- **抖音 / 小红书** — 无面向第三方的开放数据 API。

**选型建议**：
1. **YouTube** → 官方 Data API（免费+合规），不用 TikHub。
2. **Instagram 商业号** → 优先 Graph API；散户公开数据才考虑第三方。
3. **抖音 / 小红书 / TikTok（无可行官方路径）** → 第三方是唯一路。TikHub 的"单 Key + 最广覆盖 + 纯按量无承诺" 相比 Apify 的逐-actor 模型，**多平台集成成本明显更低**，适合 probe 这种要横扫多平台的场景。

## 5. 合规与风险 🛑（本轮**零验证结论** — 最大空白）

> 研究问题的整个"合规与风险"维度**未产出任何已验证发现**。以下为必须独立调研的开放风险，不是结论。

1. **数据来源合法性 / 平台 ToS / 封禁风险** — 完全未验证。抓取型 API 普遍踩各平台 ToS；账号/IP 封禁、数据中断风险真实存在（抓取业内常态）。
2. **数据字段完整度** — 无任何结论确认各端点实际返回哪些字段、是否匹配 probe schema。1010/1010 是结构完整度，非数据丰富度。
3. **更新时效 / 新鲜度** — "real-time" 只出现在营销页；文档用的是更软的 "constantly being updated"。延迟是分钟级/小时级/天级，**未知**。
4. **可靠性 / Uptime / SLA** — 无 SLA、无第三方 uptime 数据。抓取型 API 对平台反爬升级天然脆弱。
5. **服务商主体 / 历史 / 经营稳定性** — 未验证。⚠️ **直接前车之鉴**：本轮抓到的资料里，头部 LinkedIn 抓取商 **Proxycurl 于 2025 年突然关停**——抓取类供应商"说没就没"是行业系统性风险，TikHub 的企业年限/主体/可靠性口碑**完全未建立**。

**域名混淆警告**：`tikhub.co` / `tikhub.us` / `tikhub.com` 有低信任/诈骗标记。**官方只认 `tikhub.io` / `api.tikhub.io`**，所有流量目标须核对。

**引用卫生**：若干定价声明引用了已失效 URL（`tikhub.io/index.php/pricing/`、`/pricing/b2b-payment`、`/enterprise` 均 404）。**权威活页**：`tikhub.io/pricing` 和 `docs.tikhub.io/186826052e0`。

## 6. link-intel / probe 落地接入建议

### Phase 0 — 冒烟测试（先做，0 成本）
用 ~50 免费额度 + 每日签到额度，对 probe **实际需要的核心端点**（XHS/抖音/TikTok 的：视频详情、用户主页、评论、搜索）跑一次真实调用，实测三件事：
- **字段完整度**：返回字段是否覆盖 probe 目标 schema？
- **时效**：数据延迟量级？
- **成功率**：连续调用的 200 比例？重端点单价落在哪档？
→ 这是把第 5 节 5 大空白中的 2、3、4 项变成实测数据的唯一办法。

### Phase 1 — 抽象层接入（Pilot）
- 经 probe 既有 **HttpToolClient**（L1 契约）封装，单 API Key 存 `~/vault/credentials/`，仓内 PLACEHOLDER。
- **供应商抽象层**：TikHub 只作为一个 provider 实现，接口与厂商解耦——鉴于第 5 节的供应商主体风险，**必须可一键切换**（Apify / 自建抓取作 fallback）。
- 关键路径**禁单点依赖** TikHub：成功率监控 + 降级方案。

### Phase 2 — 生产化（达标后）
- 监控成功率/延迟/成本，按真实端点画像复算月成本。
- 按 2.2 阶梯，若日量稳定 >10k 可享 30%+ 折扣；>30k 到 50% 地板。
- YouTube 数据**改走官方 Data API**，不浪费 TikHub 调用。
