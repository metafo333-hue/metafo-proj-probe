## 零、导航四向定义系统（全局锚点）

> 规则：同一方向在所有层级含义一致，用户学一次全局通用。

### 空间隐喻

```
        ↑ 收起 / 历史 / 更少
        │
← 返回 ─┼─ 前进 / 展开细节 →
        │
        ↓ 展开 / 当前 / 更多
```

- **水平轴（← →）= 空间移动**：左是"回去"，右是"往前/深入"
- **垂直轴（↑ ↓）= 信息密度**：上是"收起/精简"，下是"展开/详细"

## 一、核心设计哲学

```
用户的问题是「我想了解什么」+「我要什么形式的答案」
         ↑                    ↑
     probe 理解内容         用户选输出类型
         ↓
  probe 自行判断：
  · 这个问题属于哪个信息域
  · 需要哪些数据源
  · 验证深度是多少
  · 哪些闸需要重点关注
         ↓
  在对话框里流式交付
```

**用户从不需要知道"赛道"这个词。**

## 二、输出类型系统

### 六种输出类型（+ 智能选取）

| 类型 | 核心 | 用户说法 | 报告形态 |
|------|------|---------|---------|
| **咨询** | 快速事实解答 | "X是什么情况？" "Y近况怎样？" | 1-3段 + 关键来源 |
| **竞调** | 竞争情报·格局 | "A和B的竞争""XX领域主要玩家" | 对比表 + 主体档案 |
| **尽调** | 主体背景核查 | "调查XX公司/人" "核实身份" | 实体画像 + 风险标注 |
| **方案** | 决策参考建议 | "要不要和XX合作" "投资XX值吗" | 利弊矩阵 + 结论建议 |
| **事实核查** | 主张真伪验证 | "这文章是真的吗" "核实这个数据" | 主张卡 + 裁决 |
| **研究报告** | 深度多角度研究 | "某领域趋势" "深度研究" | 完整七段报告 |
| **智能选取** | probe 自判断 | 任何输入（无需选） | 自动匹配上述之一 |

### 类型选择规则

```
输入后自动触发意图解析（1.5s）

→ probe 识别意图强度：
  • 明确问"是不是真的" / 粘贴文章URL → 自动选「事实核查」
  • 出现竞争对比词（vs/对比/格局） → 自动选「竞调」
  • 出现主体+调查词（背景/历史/可信吗） → 自动选「尽调」
  • 出现决策词（要不要/值不值/应该） → 自动选「方案」
  • 其他 → 默认「咨询」（最轻量）

用户可在对话框底部随时切换输出类型
（切换 = 重新处理，会提示"已消耗积分不退，继续？"）
```

## 三·补、认知减压设计原则

> 目标：用户不需要"学"就能用，每个时刻只有一件事需要关注。

### P1 · 每个时刻只呈现一件事

| 阶段 | 用户只需要关注 | 其他信息的处理 |
|------|--------------|--------------|
| 输入阶段 | 说清楚你想了解什么 | 输出类型默认智能选取，不打断 |
| 意图解析 | 确认 probe 理解对了 | 技术细节（赛道/数据源）折叠 |
| 检索阶段 | 看初步信号就好 | 管道详情、八闸状态默认折叠 |
| 报告阶段 | 先读摘要和关键结论 | 七段报告默认只展示 S1，其余折叠 |
| 来源验证 | 点哪条来源看哪条 | 不一次性铺开所有来源 |

### P2 · 三级信息密度（永远有"更少"可选）

```
级别  内容                      触发方式
────────────────────────────────────────────
L1   结论一句话 + 可信等级徽章   默认展示
L2   关键结论3条 + 矛盾提示      点击展开卡片
L3   完整七段报告 + 溯源链       点击「查看完整报告」
```

用户可以在任何级别停止，不需要读完。

### P3 · 专业词汇只出现一次，之后用白话

| 专业词（第一次出现时解释）| 之后替换为 |
|--------------------------|-----------|
| Admiralty 评级 | 可信等级 |
| 八闸双审 | 验证过程 |
| 对抗证伪 | 检查有没有相反证据 |
| L1/L2/L3/L4 | 采集 / 收集 / 核实 / 整理 |
| 实体消歧 | 去除重复信息 |
| PIPL | 个人信息保护 |

### P4 · 颜色只有三个语义，全局统一

| 颜色 | 语义 | 用于 |
|------|------|------|
| 🟢 绿色 | 可信 / 通过 / 好的 | 高可信内容、闸通过、A/B级来源 |
| 🟠 橙色 | 注意 / 存疑 / 需判断 | 矛盾点、C级来源、闸警告 |
| 🔴 红色 | 问题 / 拦截 / 停止 | D/E级来源、闸拦截、错误状态 |
| ⚫ 灰色 | 等待 / 次要信息 | 未处理的闸、背景内容 |

品牌蓝（#1E3A8A）和橙（#FF7A1A）只用于交互元素和品牌，**不用于语义传达**。

### P5 · 进度不用数字，用状态词

| 避免 | 使用 |
|------|------|
| 处理了 68.4% | 正在收集来源 |
| 完成了 5/8 个闸 | 核实进行中 |
| 耗时 4分23秒 | 还需约 3 分钟 |
| 置信度 87.3% | 可信度：高 |

例外：来源数量（12个来源）、积分（20积分）用数字，因为这些是用户关心的具体量。

### P6 · 空白是设计，不是浪费

- 卡片间距 ≥ 12px，不堆叠
- 每张卡片最多展示 5 条信息
- 超出 5 条的内容用「查看全部（+N）」收起
- 正文每段 ≤ 3 句，不写长段落

## 六、文案语气指南（不变，继承 v2.0）

**核心原则：**
- 精准而非绝对：「主要结论可能为真」不是「已证实」
- 主动暴露不确定：「存在口径差异，详见 S4」
- 解释专业术语：「闸3 检测此内容是否由AI生成」
- 不夸大：「12个来源支持」不是「最全面情报」

**数字使用原则：**
- 百分比仅用于客观数据（粉丝数/来源数量）
- 置信度用文字（高/中/低）不用伪精确百分比
- 来源数量用实际数字（12个）

1. **六种输出类型的命名** — 「咨询/竞调/尽调/方案/核查/研究」是否准确？有无漏掉的高频场景？
